### 2.3 Computational Resource Efficiency and Economic Viability of Agent Orchestration

The computational cost of AI agents is highly dependent on the input and output context, especially when AI agents usually work through repeated cycles of reasoning, tool use, observation, and validation. In previous chapter, we mentioned that completeness and relevance of the context may directly affect the output quality of AI agents, but it also increases token consumption and inference cost, especially when the same information is reconstructed across multiple stages of the workflow.

Early agentic approaches such as ReAct has demonstrated using LLM to generate reasoning traces and task-specific actions, to allow reasoning traces help the model to track, induce and update action plans, and allow task-specific actions to interface with and gather additional information from external sources (Yao et al., 2022). At the same time, these reasoning-action loops require repeated model calls and may cause context to accumulate continuously. In complex software engineering tasks, this creates a trade-off between autonomy and efficiency, more autonomous workflows may reduce human intervention, but they can also increase computational cost if the agent repeatedly loads similar context or performs unnecessary intermediate steps.

To address memory and context limitations, several studies have proposed methods for retaining, compressing, and retrieving relevant information only. Reflexion stores verbal feedback in an episodic memory buffer to induce better decision making, so that agents can learn from previous attempts without updating model weights (Shinn et al., 2023). MemGPT proposes a memory management approach inspired by operating system memory hierarchy, allowing information to store in main and external memory instead of forcing all information into the active context window (Packer et al., 2023). These approaches show that by separating immediate working context from longer-term memory can improve the agent efficiency, rather than repeatedly resending the full context.

AI agents are not always necessary especially if computational cost is one of our consideration. Xia et al. (2024) proposed Agentless, a simplified approach based on localization, repair, and patch validation, and showed that a less autonomous but more structured workflow can achieve competitive performance at lower cost. This work is important because it challenges the assumption that introducing more agent into the workflow can produce better software engineering outcomes. Instead, it suggests that context selection, hierarchical localization, and constrained patch generation can reduce unnecessary computation while maintaining effectiveness and performance of the AI agents.

SWE-agent demonstrates that agent-computer interface design affects how well language-model agents can navigate repositories, edit files, and execute tests (Yang et al., 2024). More recently, Fan et al. (2025) argues that software engineering agents should be evaluated not only by correctness or issue resolution rate, but also by resource consumption, including token usage and time. The authors identify problems such as “token snowball” and “expensive failures,” where agents consume substantial resources while making little or no progress. This supports the need to evaluate agent workflows using cost-efficiency metrics, rather than productivity metrics alone.

Recent context-management research further supports this argument. Liu et al. (2025) proposed Context as a Tool, where context maintenance is treated as an explicit callable tool rather than a passive accumulation of conversation history. Their approach organizes context into stable task semantics, condensed long-term memory, and high-fidelity short-term interactions, allowing agents to compress historical trajectories at suitable milestones. This demonstrates the effective coordination requires not only better modelling but also controlled preservation, compression, retrieval, or loss of contextual information.

Existing studies have proposed different mechanisms to improve LLM-based software engineering agents, such as memory buffers, context compression, hierarchical localization, and agent-computer interfaces. However, most of the evaluations is still conducted on benchmark repositories or issue-resolution datasets. Fewer studies examine them in a large-scale production environment. In such environments, inefficient context management may increase computational cost, review and validation effort.

In this study, Trade-Harness aims to reduce the inefficient context utilization through six orchestration layers, the Information Boundary and Tool System layer narrow down the context retrieved and the tool use, then Memory and State layer keep the task progress, intermediate decisions and information across the workflow stages, so the agent does not need to rebuild context in every loop. Trade-Harness is expected to reduce redundant context loading and improve the economic viability of agent-assisted development. Therefore, this study evaluates whether Trade-Harness can improve computational resource efficiency compared with a conventional prompt-based workflow, using metrics such as lines of code per million tokens and token cost per issue.
