### 2.1 Autonomy, Orchestration, and Human-in-the-Loop Control in AI-Assisted Development Workflows

AI-assisted software development has changed the way developers perform programming tasks, but its effect on delivery lead time depends on more than the speed of code generation. Delivery lead time includes not only implementation, but also task understanding, context reconstruction, planning, validation, debugging, code review, and integration into the wider codebase. Therefore, the productivity effect of AI coding tools should be examined from the perspective of workflow structure, level of autonomy, and human-in-the-loop control, rather than from code generation speed alone.

Existing studies show that AI coding assistants can improve local implementation speed. Peng et al. (2023) found that developers that using GitHub Copilot are able to complete the task 55.8% than developers that are manually coding. In Song et al. (2024) study, they found that developers using GitHub Copilot can increase project-level code contributions by 5.9%, and it is driven by a 3.4% rise in developer coding participation and 2.1% increase in individual productivity. This suggests that using AI coding assistants can reduce coding effort. However, faster code generation does not automatically translate into shorter delivery time, using GitHub Copilot also leads to an increase in coordination time by 8% because time spent in more code discussions and review session. This means that we should take these factors into account when measuring delivery efficiency.

Besides that, the way developers use AI tools is also a factor affecting delivery efficiency. The quality of prompts input is a critical factor when using generative AI, as it directly determines the quality of the output. In a prompt-based workflow, the developer decides what information to provide, how to decompose the task, which files or dependencies are relevant, and validate whether the generated output is correct. As a result, developers may need to repeatedly explain requirements, paste code snippets, clarify constraints, correct wrong assumptions, and validate generated changes across multiple conversational turns. Otten et al. (2025) found that software engineers commonly use generative AI through iterative multi-turn conversations, and that complex code generation and debugging remain challenging compared with more predictable tasks such as documentation. This also confirms that when developers are shifted to prompt-based AI coding, developer no longer just focus on how the code is implemented, but also on the prompt management, context reconstruction, and output verification.

We can consider the issues above from the perspective of automation and autonomy. Parasuraman et al. (2000) describe automation can be applied can support information acquisition, information analysis, decision selection, and action implementation. In AI-assisted software development, prompt-based coding assistants provide partial automation for code suggestion, explanation, or generation, but the developer still need to control and connect the entire development workflow themselves, including task planning, context selection, execution control, validation, and integration. Therefore, prompt-based AI coding can only be considered as a low-autonomy AI-assisted development.

Recent work on developer-AI collaboration also shows that AI assistance should not be treated as a single interaction pattern. Treude and Gerosa (2025) propose a taxonomy of human-AI collaboration in software engineering, including interaction types such as auto-complete code suggestions, command-driven actions, and conversational assistance. This taxonomy is useful because it shows that the effectiveness of AI tools depends not only on model capability, but also on how developers interact with the AI system, how much control is delegated, and how outputs are incorporated into the development workflow. From this perspective, prompt-based coding and agentic workflows differ not merely in tooling, but in the degree of autonomy and workflow control assigned to the AI system.

Agentic software engineering workflows can address the limitations of prompt-based coding by moving from isolated prompt-response interactions toward structured, goal-directed execution. In an agentic workflow, the AI system can decompose tasks, inspect repository files, modify code, run tools, observe failures, and iteratively enhance itself based on feedback. SWE-bench demonstrates that resolving issues frequently need the understanding to make changes across multiple functions, classes and files, then calling for models to interact with execution environment, it processes an extremely long contexts and able to perform complex reasoning that goes far beyond traditional code generation tools (Jimenez et al., 2024). In Yang et al. (2024) study, they propose a custom agent-computer interface (ACI) and prove that enhancing an agent’s ability to create and edit code files, navigate repositories and execute tests can achieving a better performance compare to non-interactive LLMs agents. These studies indicate that increasing the level of autonomy and interactivity of AI agent can improve its performance.

However, increasing the level of autonomy cannot truly improve the delivery efficiency, because the time cost of coordination mentioned earlier still exists, and AI agent may still misunderstand requirements, select irrelevant files, make unsafe changes, or continue ineffective reasoning loops. Therefore, agentic development requires a structured orchestration workflow. In this study, orchestration refers to the structured coordination of task decomposition, context preparation, tool execution, memory, validation, recovery, and human decision points, it can define what the agent is allowed to do, what information it should use, how intermediate outputs should be checked, and when human intervention is required.

Therefore, human-in-the-loop control is another core element of agentic software engineering. The purpose of human involvement in the agent loop is not about controlling every step of the process, but enabling humans to take a supervisory role. In a prompt-based system, humans are needed to manually prompt the agent to proceed to next step, but in a structured orchestration workflow, the human role is to monitor the agent’s behaviour and output. Takerngsaksiri et al. (2025) introduce a human-in-the-loop LLM-based agent framework, HULA that allows software engineers to refine and guide agents during coding plan and source code generation. The results show that HULA can minimize the overall development time and effort, especially in planning and writing code for tasks.

In this study, Trade-Harness serves as a structured orchestration framework for controlled agentic front-end development that does not rely on free-form prompting. Instead, it organizes the development process through defined workflow stages, including information boundary setting, tool-based context discovery, execution orchestration, memory and state management, evaluation, validation, and recovery. It is expected to improve delivery lead time, reduce repeated context reconstruction and improve the continuity of task execution.

Therefore, the research gap addressed in this study is not whether AI can generate code faster in isolated programming tasks since existing studies already suggest that AI coding assistants can improve implementation speed. This study evaluates whether Trade-Harness can reduce delivery lead time compared with a conventional prompt-based AI coding workflow while maintaining acceptable implementation quality and validation reliability.
