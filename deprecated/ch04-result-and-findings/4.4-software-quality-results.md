## 4.4 Software Quality Results (RQ2)

> **Provisional results (dataset snapshot reviewed 2026-11-22):** 548 Jira issues, ten developers, 302 baseline tasks and 246 Trade-Harness tasks. The final research-sample definition remains open. Findings below are descriptive; tasks were not randomly assigned.

Software quality is assessed through the **final task-level E2E test pass rate** and **task-level defect density**. No pooled defect-density measure is used in this chapter.

### 4.4.1 Final E2E Pass Rate

The pass rate for each task is its number of passing applicable JSON test cases divided by all applicable cases. Failed and unexecuted cases remain in the denominator; missing final reports are not interpreted as 0%.

**Table 4.7. Final task-level E2E pass rate (%)**

| Statistic | Baseline | Trade-Harness |
|---|---:|---:|
| Valid tasks (n) | 300 | 246 |
| Mean | 91.55 | 93.35 |
| Median | 100.00 | 100.00 |
| Standard deviation | 12.66 | 11.25 |
| IQR | 16.67 | 12.50 |
| Range | 50.00–100.00 | 33.33–100.00 |

The mean task-level E2E pass rate is **91.55%** for the baseline and **93.35%** for Trade-Harness, a difference of **1.79 percentage points**. Both medians are 100%. This suggests that the difference is concentrated among tasks whose final reports contain failures or unexecuted cases, rather than in the median result.

### 4.4.2 Defect Density

For task `i`, defect density is defined as `confirmed defects_i / (changed production LOC_i / 1,000)`. Changed LOC includes added and absolute deleted production-code lines, excluding generated and test code.

**Table 4.8. Task-level defect density (confirmed defects / 1,000 changed production LOC)**

| Statistic | Baseline | Trade-Harness |
|---|---:|---:|
| Valid tasks (n) | 301 | 246 |
| Mean | 3.06 | 2.41 |
| Median | 0.94 | 0.55 |
| Standard deviation | 5.54 | 4.11 |
| IQR | 3.92 | 3.10 |
| Range | 0.00–47.62 | 0.00–27.78 |

The mean task-level density is **3.06** for the baseline and **2.41** for Trade-Harness; the medians are **0.94** and **0.55**, respectively. Defect density is strongly affected by small changes: a few confirmed defects can produce a large ratio when only a small number of production-code lines changed. These values are retained and reported as part of the task-level distribution.

Issue **FBU-1471** has zero changed production LOC, so its defect density is undefined and excluded from Table 4.8. The defect count uses the existing task-level `confirmed_defects` field (**634 total across both workflows**) rather than all entries in the raw defect register. Nine entries are flagged as after the source dataset's cutoff; the exact extraction date needs final confirmation (Section 4.2.3). No separate fixed observation window is introduced.
