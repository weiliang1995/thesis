#### 2.1.1 LLM-Based Agent Execution Model

A developer can use a general-purpose generative AI application such as ChatGPT to ask how a function works or request a code suggestion. In this question-and-answer mode, the developer reads the response and decides what to do next. A coding agent can take part in the development environment more directly: with access to appropriate tools, it can inspect repository files, edit code and run commands. The distinction here is how the system is used, not the name of the model or application. The same underlying model can support either mode, and a coding agent does not remove the developer from the process (Yang et al., 2024; Anthropic, 2024).

An agent also needs a way to decide what to do after each step. Wang et al. (2024) describe LLM-based agents in terms of profiling, memory, planning and action. In a coding task, planning concerns the next step towards the requested change; memory helps retain information from earlier work; and action connects the agent's decisions to its tools and environment. These are useful functions for explaining agent behaviour, rather than a fixed set of components that every coding agent must implement in the same way.

ReAct gives a concrete example of this execution process. Yao et al. (2023) interleave reasoning with actions and observations: the agent selects an action, receives information from an external source or environment, and uses that observation to inform its next step. Applied to software development, an agent might search for the component affected by a request, inspect its dependencies, modify a file, and then use a test result to decide whether further changes are needed. This coding example illustrates the loop; it is not one of the experimental settings evaluated in the ReAct paper. ReAct is likewise one approach to agent execution, not a requirement for all coding agents.

The agent's autonomy lies in choosing some of these actions as the task unfolds. It does not imply unrestricted control. Available tools, instructions, environmental feedback and human review shape what the agent can do. Anthropic (2024) distinguishes a workflow, in which code defines the path through LLM and tool calls, from an agent, in which the model dynamically directs its process and tool use. These arrangements can be combined: a predefined workflow may set stages or checks while an agent decides how to carry out a task within them. This distinction is relevant to the two workflows compared in this study, since both use an agent-capable coding tool; they differ in how its activities are organised.

In either arrangement, execution begins with a task expressed by a person. The agent needs to know the intended change, any constraints and what would count as an acceptable result before it can choose useful actions. How developers formulate those instructions is the starting point for prompt engineering, discussed in the next section.
