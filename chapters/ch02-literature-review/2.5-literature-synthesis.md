### 2.5 Literature Synthesis

A change that saves effort at one stage of an AI-assisted task can have a different effect on the task as a whole. In Becker et al. (2025), implementation time increased when AI assistance was available, even though developers spent a smaller share of their time actively coding in the subset of issues with screen recordings. In a study of interrupted coding-agent tasks, KC and Budathoki (2026) found that passing task context to a successor agent reduced the actions and prompt tokens needed after takeover, while differences in issue resolution were smaller and varied by model. These findings motivate examining time, defects, test results, and model resource use in the same comparison. The reviewed studies provide limited evidence on how these outcomes vary together when developers use the same coding agent under different workflows in multi-repository enterprise front-end development.

Trade-Harness organises development into explicit stages, carries task context between them, and incorporates validation into the workflow. The value of these steps may depend on the work involved. Agentless achieved competitive results on SWE-bench Lite using a fixed sequence of localisation, repair, and patch validation (Xia et al., 2024). This result motivates asking how much structure different development tasks need. For a localised change, there may be little task-specific information to carry between stages. A cross-repository change may involve dependency findings and implementation decisions that a later stage needs, while preparing a handoff and running checks can also add work. Comparing the workflows within task complexity levels allows the study to examine whether the observed differences vary with estimated development effort.

This study therefore uses a quasi-experimental design to compare Trade-Harness with a developer-managed, prompt-based workflow. Both workflows use Claude Code in the same enterprise front-end development setting. The comparison examines delivery lead time, defect density, final E2E test pass rate, and token cost per resolved issue across task complexity levels. Chapter 3 describes the two workflows, how tasks are classified, and how the outcomes are measured.
