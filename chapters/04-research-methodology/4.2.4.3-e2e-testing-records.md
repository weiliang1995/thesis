##### 4.2.4.3 E2E Testing Records

Each feature-development task has its own JSON test-case document. In both workflow conditions, the agent uses the task's cases to generate E2E test code and execute it using Playwright MCP. The generated E2E report is saved in the repository under `docs/e2e-test`, with the file named after the development branch. The branch association is used to link each report to the relevant Jira issue; tasks are not repeated under both workflows.

For each task, the applicable cases in the JSON document provide the E2E pass-rate denominator, and cases passing in the final report provide the numerator. Failed, unresolved, and unexecuted cases are not treated as passes. Test-script correction loop counts are collected as a supplementary measure only where the saved report or available execution record supports a reliable count. The location and naming convention of a final report alone do not establish that individual correction loops are logged. Missing or untraceable testing records are identified in data preparation.
