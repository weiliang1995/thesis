##### 4.2.4.3 E2E Testing Records

Each feature-development task has its own JSON test-case document. In both workflow conditions, the agent uses the task's cases to generate E2E test code and execute it using Playwright MCP. The generated E2E report is saved in the repository under `docs/e2e-test`, with the file named after the development branch. The branch association is used to link each report to the relevant Jira issue; tasks are not repeated under both workflows.

For each task, the applicable cases in the JSON document provide the E2E pass-rate denominator, and cases passing in the final report provide the numerator. Failed, unresolved, and unexecuted cases are not treated as passes. The saved E2E reports also record the number of test-script correction loops performed for the task. This count is collected as a supplementary process measure alongside the final pass rate. A loop refers to diagnosing an E2E failure, correcting the generated test script, and rerunning the test; the initial execution is not a correction loop. The reports are linked to Jira issues through their branch names, and missing or untraceable testing records are identified during data preparation.
