#### 4.1.3 Research Variables

The study examines one independent variable and three groups of dependent variables. Several control measures are applied to improve comparability between the two workflow conditions.

**Independent Variable**

The independent variable is the AI-assisted development workflow used to complete each task. Table 4.2 shows that the details of baseline condition and intervention condition in different stage.

*Table 4.2 Workflow Condition Comparison*

| **Element**      | **Baseline**                                      | **Intervention**                                                  |
|------------------|---------------------------------------------------|-------------------------------------------------------------------|
| Developer Role   | Manually constructs prompts and selects context   | Supervises staged execution pipeline                              |
| Entry Point      | Claude Code CLI with ask/plan/accept edits mode   | Command-based                                                     |
| Context Handling | Manual context selection by developer             | Repository-aware context assembly                                 |
| Task Structure   | Free-form iterative prompting                     | PRD parsing, TRD generation, task decomposition, agent assignment |
| Code Generation  | AI suggests or edits code with developer approval | Staged implementation through predefined execution rules          |
| Validation       | Developer manually runs checks and prompts fixes  | Validation gates for type correctness and interface consistency   |
| Testing          | Manually prompted or manually executed            | Vitest/Playwright generation and iterative self-correction        |
| Output Control   | Developer reviews and approves changes            | System proceeds only after validation criteria are satisfied      |

**Dependent Variables**

The dependent variables in this study can be categorized into three types:

- **Delivery efficiency:** Delivery lead time, measured in days from the transition of the Jira issue to *In Progress* until QA staging.

- **Software quality:** Integration testing pass rate and defect density, expressed as the number of defects per thousand lines of code.

- **Computational cost:** Lines of code generated per million tokens and token cost per resolved issue.

**Controlled Variables**

The controlled variables for this study are the tools and environment used. We will use the same large language model, Claude Sonnet 4.6, and our IDE is VS Code, with the primary interface for interacting with the model, Claude Code CLI. To avoid inconsistencies in the output of different models, we will not switch to other models during these 12 weeks.
