#### 4.1.2 Task Selection, Classification and Developer Assignment

In this study, all tasks are real; there are no dummy tasks. These tasks are either requirements proposed from product managers or code refactoring and bug fixing resulting from technical debt. All tasks are created and recorded using Jira. Only tasks that are properly recorded, and those with traceable code changes and commits on GitLab, are included in this study. These tasks only involve front-end modifications; back-end, mobile, architectural, product research, and tasks without data are excluded.

The tasks included in this study are categorized into simple, medium, and complex based on their complexity. Table 4.1 shows the details of the categorization, which is mainly based on the estimated effort and the dependency requirement of the tasks.

*Table 4.1 Task Complexity Classification*

| **Complexity Level** | **Estimated Effort** | **Dependency Requirement**                                          | **Description**                                                                               | **Examples**                                                                              |
|----------------------|----------------------|---------------------------------------------------------------------|-----------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------|
| Simple               | ≤ 1 day              | No backend integration or external dependency                       | Isolated frontend changes with limited scope and minimal system impact                        | CSS/layout adjustments, announcement modal, advertisement banner, minor UI updates        |
| Medium               | 2–4 days             | Requires backend coordination and API integration                   | Feature-level tasks involving new or modified API contracts and data integration              | Order query panel with backend support, dashboard data visualization with new endpoints   |
| Complex              | \> 4 days            | Requires new module design and cross-component / system integration | Large-scale feature development involving new business logic, modules, and state coordination | New order type module, end-to-end feature with new APIs and frontend architecture changes |

This study will select two developers, refers to developer A and developer B, from the development team as research participant. They will use both workflows to complete the tasks. Over 12 weeks, the technical lead will assign tasks to them as evenly as possible across the two different workflows, covering various levels of complexity. This research design is aimed to minimize individual developer bias.

Developer A and B have approximately two and three years of experience in front-end development, both of them are familiar with the selected cryptocurrency trading system and have practical experience using Claude Code, which is the selected AI coding assistant in this study.
