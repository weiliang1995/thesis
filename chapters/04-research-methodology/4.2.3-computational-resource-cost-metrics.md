#### 4.2.3 Computational Resource Efficiency and Cost Metrics

This study evaluates computational resource use through changed lines of production code per million tokens and the LLM token cost associated with each completed feature-development task. Both measures use task-level records from GitLab and the enterprise LLM gateway. The gateway provides input and output token counts and associated usage costs, but does not separate token consumption by activities such as planning, implementation, or validation.

**Changed LOC per Million Tokens**

This measure relates the final volume of production-code changes to the total recorded input and output tokens for a task.

$$Changed\ LOC_i=Added\ LOC_i+|Deleted\ LOC_i|$$

$$Tokens_{total,i}=Tokens_{input,i}+Tokens_{output,i}$$

$$L_i=\frac{Changed\ LOC_i}{Tokens_{total,i}}\times1{,}000{,}000$$

where $L_i$ is changed lines of production code per million tokens for task $i$. Changed LOC is calculated from the final task-attributable GitLab diff using the same production-code scope as the defect-density measure in Section 4.2.2. The token denominator is the sum of input and output tokens recorded by the gateway and linked to that task. The measure describes code-change volume relative to token consumption; it is not a direct measure of functional value or developer productivity. Tasks with missing or zero recorded token totals are flagged for data review rather than assigned an artificial ratio.

**Token Cost per Resolved Issue**

The LLM token cost for task $i$ is the total recorded gateway cost associated with that task, expressed in US dollars:

$$C_i=\sum_{j=1}^{m_i}c_{ij}$$

where $c_{ij}$ is the recorded cost of LLM request $j$ linked to task $i$, and $m_i$ is the number of those requests. For each workflow condition $w$, the average token cost per resolved issue is:

$$\overline{C}_{w}=\frac{1}{N_w}\sum_{i=1}^{N_w}C_i$$

where $N_w$ is the number of completed, eligible issues in that workflow condition with available cost records. Task-level costs can also be compared by task-complexity category. This metric covers recorded LLM usage charges, not developer labour or other infrastructure costs.

The analysis uses the total task-associated gateway usage without attributing individual tokens or costs to internal agent stages. Data extraction, issue matching, and the handling of incomplete usage records are addressed in Sections 4.2.4 and 4.2.5.
