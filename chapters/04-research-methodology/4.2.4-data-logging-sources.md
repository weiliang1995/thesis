#### 4.2.4 Data Sources and Collection

The study uses records produced during normal development, without adding custom telemetry to the coding workflows. An existing AI-development analytics dashboard consolidates Jira task information, GitLab code-change metrics, and LLM usage and cost records from the enterprise gateway. The dashboard provides an integrated view of these measures, while Jira, GitLab, and the gateway remain their underlying data sources. E2E test reports are stored separately in the repository under `docs/e2e-test`.

The Jira issue is the unit of analysis. Its identifier is used to assemble task-level measurements from the available dashboard and source records. E2E reports are named using the development branch name, so they are associated with tasks through the branch-to-issue relationship. This association is checked when assembling the dataset rather than assuming that all systems use the Jira identifier as a native field. Data reconciliation, incomplete records, and analysis procedures are described in Section 4.2.5.
