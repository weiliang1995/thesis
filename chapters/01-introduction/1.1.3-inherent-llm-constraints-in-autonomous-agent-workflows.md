#### 1.1.3 Inherent LLM Constraints in Autonomous Agent Workflows

AI agent’s reasoning ability and code generation skills rely heavily on the availability of adequate system context for the underlying large language model (Huang et al., 2025). If the information is inadequate, the AI agent may make incorrect assumptions, results in inconsistency or invalidity of output.

It is even more critical to consider this constraint in multi-repository front-end architectures. Common business logic, shared components, types and dependencies spread across different repositories and modules. It is challenging to keep track of the connections throughout the workflow, especially in situations where context has to be reconstructed.

This means that generated code from agents might seem correct at a local level but violate repository-level rules. Structural issues often seen in generated code include improper component interfaces, wrong type assumptions, improper usage of APIs, reference to missing modules, and implementation that contradicts architectural constraints.

These limitations show that increasing the level of autonomy is not enough for dependable software development. To achieve a reliable agentic workflow, there needs to be a proper structure to control information borders, gathering repository-aware context, maintaining task states, managing execution phases, and checking the produced output. This motivate the study of Trade-Harness as a structured orchestration workflow for agent-based front-end development.
