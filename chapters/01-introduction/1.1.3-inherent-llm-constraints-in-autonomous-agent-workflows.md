#### 1.1.3 Constraints in Enterprise Agentic Workflows

Applying coding agents to enterprise development introduces several challenges, particularly when tasks involve large codebases, dependencies between modules, and project-specific requirements.

The first challenge is understanding the relationships between different parts of a system. In multi-repository front-end development, shared components, type definitions, API interfaces, and business logic may be maintained separately. Developers must understand how a change in one location affects other modules. Previous research has shown that language models may have difficulty using relevant information in long input contexts (Liu et al., 2024). Eghbali and Pradel (2024) also examined how insufficient project-specific information can contribute to incorrect API references in generated code.

The second challenge is maintaining consistency with the project's development practices. Different teams may follow different conventions for component reuse, task planning, testing, review, and deployment. Coding agents can be configured with repository instructions and development tools, but the availability of these capabilities does not guarantee that every project requirement will be followed throughout a multi-stage task. Developers may still need to provide additional instructions, inspect intermediate results, and correct decisions that do not match the project's expectations.

Another challenge is the non-deterministic behaviour of LLM-based agents. The same development request does not necessarily produce identical decisions or outputs across different executions. This makes validation important when changes must satisfy specific interfaces, coding rules, and integration requirements.

These challenges do not mean that native coding agents are incapable of working on complex projects. Rather, their effectiveness may depend on how context, execution, and validation are managed within the development environment. A structured workflow offers one possible approach, although additional coordination and validation steps may also introduce execution overhead.
