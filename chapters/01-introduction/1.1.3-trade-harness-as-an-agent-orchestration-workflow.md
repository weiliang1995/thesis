#### 1.1.3 Agent Orchestration in Software Engineering

The challenges of context management, memory persistence, and non-deterministic agent behaviour also raise questions about how coding agents are coordinated across multi-step development tasks. While agents can decide and perform individual actions autonomously, orchestration concerns how those actions are organised within a larger workflow. An agent orchestration workflow can coordinate task execution, relevant context, tool access, state management, and validation without changing the underlying language model.

Agent workflows can be organised with different degrees of control. In an agent-driven workflow, the agent determines its next steps from the current task and the feedback it receives. A more structured workflow defines certain stages, rules, or checks in advance. These approaches can also be combined: for example, a workflow may require planning and validation stages while allowing the agent to decide how to implement changes within each stage. Orchestration therefore does not necessarily require multiple agents, nor does it remove the agent's ability to make decisions.

Several mechanisms may be used to organise agent execution, including context management, tool integration, execution coordination, memory and state management, observability, and validation. Table 1.1 groups these mechanisms by their roles in an orchestration workflow. This grouping is used to describe common design concerns; it is not presented as a standard six-layer architecture.

*Table 1.1 Common Mechanisms in Agent Orchestration Workflows*

| **Mechanism** | **Purpose** |
|---|---|
| Context Management | Identifies and provides task-relevant requirements, repository information, and project constraints. |
| Tool Integration | Enables agents to access development tools, source files, and external systems. |
| Execution Orchestration | Coordinates task planning, execution stages, and feedback between activities. |
| Memory and State Management | Maintains relevant information, intermediate decisions, and task state across workflow stages. |
| Evaluation and Observability | Records execution traces and results to support monitoring and review. |
| Constraints and Validation | Applies workflow rules and checks outputs against defined requirements. |
