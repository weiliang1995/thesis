#### 1.5.2 Definition of the Orchestrated Workflow

This study compares two AI-assisted development workflows: a conventional developer-managed prompt-based workflow and Trade-Harness, a structured agent orchestration workflow. Both conditions use Claude Sonnet 4.6 through Claude Code CLI in the same development environment.

The conventional workflow refers to the developer's direct use of Claude Code CLI to plan, implement, and validate development tasks. Developers manage interactions through prompts, decide which context is needed, and coordinate the activities required to complete the task. The baseline retains Claude Code's native capabilities, such as repository inspection, file editing, command execution, and support for project-level instructions. It is therefore not treated as a non-agentic coding assistant.

In the Trade-Harness workflow, developers provide task requirements while the orchestration process organizes task decomposition, context handling, agent execution, and validation according to predefined rules. The workflow manages the information and tools used at different stages, maintains relevant task state, and applies validation conditions before allowing execution to proceed.

The main difference between the two conditions is how agent activities are coordinated, rather than the underlying model or its basic coding capabilities. Trade-Harness does not replace developers or eliminate the need for human review. It adds an explicit workflow structure intended to support consistent execution under the project's development requirements.

The detailed differences between the two conditions, including task structure, context handling, validation, and developer involvement, are described in the research methodology.
