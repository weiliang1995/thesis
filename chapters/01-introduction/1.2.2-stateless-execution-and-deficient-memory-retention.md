#### 1.2.2 Context Continuity and Software Quality

In front-end development, code changes often involve dependencies between application state, component interfaces, type definitions, APIs, and shared libraries. When coding agents work with incomplete context or fail to retain important information from earlier development stages, they may misunderstand requirements or make incorrect assumptions about existing code. This can lead to code generation errors, such as referencing non-existent APIs, modifying incompatible components, or overlooking project-specific constraints. Eghbali and Pradel (2024) studied hallucinated API references in code generation and explored how providing relevant project information could help reduce such errors.

Although coding agents can validate their outputs through testing and feedback loops, these checks may not detect every issue. For example, if the agent overlooks a dependency or misunderstands a requirement, its validation process may also fail to consider the affected functionality. As a result, some errors may remain undetected, even after the generated code has passed the agent's validation steps.

In prompt-based workflows, context continuity depends on the developer's instructions and the agent's built-in context management mechanisms. Structured agent orchestration workflows can organise context selection, memory retention, and validation across development stages (Packer et al., 2023; Liu et al., 2025). They may also assign separate responsibilities for implementation and validation, allowing generated changes to be checked against predefined requirements. However, providing more complete and relevant context does not necessarily guarantee correct code generation or effective validation. Whether these mechanisms translate into measurable improvements in software quality requires further empirical evaluation.
