#### 4.3.3 External Validity

The study is conducted in one industrial front-end system for a cryptocurrency trading platform. Its large codebase, shared component libraries, and cross-repository dependencies provide a relevant setting for evaluating structured orchestration, but the development practices and integration demands may differ from those in smaller projects or other industries. The selected work covers new features and enhancements in this environment, so the results are not intended to represent backend-only development, standalone defect fixes, or independent refactoring.

Only two front-end developers participate over a 12-week period. Both are familiar with the system and with Claude Code, which helps limit differences caused by unfamiliar tools but restricts the range of developer backgrounds represented. The study does not establish how the workflows would perform for larger teams, novice developers, or developers with different levels of AI-tool experience.

Both conditions use Claude Code CLI with Claude Sonnet 4.6 and the same underlying development environment. Different models, agent runtimes, testing infrastructure, or repository structures may change the balance between orchestration overhead and its possible benefits. The results are therefore most directly applicable to teams with comparable tasks, tools, and engineering constraints; broader applicability requires further study in other settings.
