#### 1.2.3 Token Consumption and Computational Efficiency

The computational cost of coding agents is largely associated with token consumption during model interactions. LLM providers generally charge different rates for input and output tokens, while cached inputs may be charged at lower rates. Input tokens include developer instructions, repository context, conversation history, and tool responses, whereas output tokens are generated by the model. As coding agents perform multiple development activities, repeated model interactions contribute to the overall token consumption of a task.

Agentic workflows may involve multiple reasoning and action loops, repeated tool interactions, and additional context provided during execution (Yao et al., 2023). More complex workflows may also involve multiple agents, each requiring its own context and model interactions. However, increasing the number of agents, execution loops, or the amount of context does not necessarily lead to better task outcomes. Fan et al. (2025) highlighted the importance of evaluating coding agents under resource constraints, considering task success alongside token consumption, execution time, and cost.

In conventional prompt-based workflows, token consumption comes from developer instructions, agent-generated outputs, tool interactions, and repeated corrections. Structured agent orchestration workflows may reduce redundant context handling through task-specific context management and persistent task states. However, additional planning, agent coordination, and validation steps may also increase token consumption. The key concern is whether the potential savings in token consumption outweigh the additional overhead introduced by orchestration.
